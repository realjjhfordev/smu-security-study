# PART 5·6·7 반영 내역

PART 5: SECTION 19~30, Q273~Q423

PART 6: SECTION 31~38, Q424~Q527

PART 7: SECTION 39~42, 연결 기출 번호 미제공으로 빈 목록 유지. 번호를 임의 생성하지 않았습니다.

원자료 마지막의 내용 없는 ‘정보보호 관련 법규’ 제목은 확정 목차 밖이므로 새 SECTION으로 만들지 않았습니다. 42개 단원 구조는 유지됩니다.

SECTION 30은 ‘최신 네트워크 보안 동향’, SECTION 40은 ‘정보보호 위험관리’로 확정 목차와 일치시켰습니다. 반복 소제목 번호와 첨부되지 않은 사진 참조를 정리했습니다. 원문의 고정폭 설명·명령·수식은 코드 블록으로 보존했습니다.

## 내용 수정

- 이전: - 는 제한 시간 내 응답을 받지 못했다는 뜻이다.
  수정: - `*`는 제한 시간 내 응답을 받지 못했다는 뜻이다.
  이유: traceroute 출력 기호 누락 복원

- 이전: 수신자의 공개키로 메일을 암호화하고, 수신자는 자신의 개인키로 복호화합니다.
  수정: 메일 본문은 대칭키로 암호화하고, 그 세션키를 수신자의 공개키로 보호합니다. 수신자는 개인키로 세션키를 복원한 뒤 본문을 복호화합니다.
  이유: PGP 하이브리드 암호 방식 정정

- 이전: SA는 단방향이다.
  수정: IPsec SA는 단방향이다. IKE SA는 양방향 협상 통로이므로 구분한다.
  이유: IPsec SA와 IKE SA 구분

- 이전: 자료의 핵심 관계는 `위험 = 자산 가치 × 위협 수준 × 취약성`이다.
  수정: `위험 = 자산 가치 × 위협 수준 × 취약성`은 일부 평가 방법의 개념식이며, 모든 위험평가에 적용하는 보편적 계산식은 아니다.
  이유: 위험 계산식의 적용 범위 명시

- 이전: `전체 위험 − 보호대책으로 줄인 위험 = 잔여 위험`
  수정: `잔여 위험 = 보호대책 적용 후 다시 평가한 위험`
  이유: 정성 등급을 단순 뺄셈하는 오해 방지

- 이전: 서비스가 최대 얼마 동안 멈춰도 되는가?
  수정: 서비스를 얼마 안에 복구할 것을 목표로 하는가?
  이유: RTO와 최대 허용 중단시간 구분

- 이전: `RTO = 서비스 중단 허용 시간`
  수정: `RTO = 목표 복구 시간`. 최대 허용 중단시간(MTD/MTPD)과 구분하며, 업무 재개·검증에 필요한 시간도 고려해 더 짧게 설정한다.
  이유: 목표와 허용 한계 구분

- 이전: *교재에 제시된 3부 구성 기준.*
  수정: *아래 1~3부는 기존 CC v3.1의 구성이다. CC:2022는 4부(평가 방법·활동 명세 프레임워크)와 5부(미리 정의된 보안 요구사항 패키지)를 추가한 5부 구성이다.*
  이유: CC 버전별 구성 구분

- 이전: 정책 → 표준 → 지침 → 절차
  수정: 정책을 바탕으로 표준·지침·절차를 마련
  이유: 지침이 절차의 필수 상위 단계인 것처럼 보이는 고정 계층 해소
