# 데이터와 권한

[문서 안내](../README.md)

다음은 구현해야 할 논리 데이터 구조다. 실제 테이블명·자료형·API 경로는 상세 설계에서 결정한다. 정답과 해설을 포함한 보호 필드는 공개 문제 조회와 분리한다.

| ID 및 데이터 | 등급 | 핵심 항목 | 관계와 무결성 |
| --- | --- | --- | --- |
| DR-01 사용자 | A | 사용자 ID, 이메일, 닉네임, 가입 시각, 계정 상태 | 인증 사용자와 프로필 연결. 비밀번호 원문 자체 저장 금지 |
| DR-02 학습 자료 | A | PART·SECTION·개념·출제포인트 ID, 요약 본문, 관련 Q번호 | 단원에 개념 여러 개. 문제에 대표 개념 1개와 관련 개념 여러 개. 미등록 참조는 별도 구분 |
| DR-02 문제 | A (버전 필드는 C) | 원본 Q번호, 버전, 종류, 본문, 보기 4개, 정답 번호, 기본 해설, 검수 상태 | Q번호 고유. 버전별 정답·보기 보존. 일반 기출과 개인 AI 문제 ID 영역 분리 |
| DR-03 제출 기록 | A (요청 ID·문제 버전은 C) | 제출 ID, 사용자 ID, 문제 ID·버전, 선택 답, 확신도, 정오답, 풀이 종류, 서버 시각, 요청 ID | 사용자와 문제에 연결. 동일 요청 ID는 1회 처리. 최초 제출은 Q번호 단위로 결정 |
| DR-03 학습 완료 | A | 사용자 ID, 단원 ID, 완료 상태, 변경 시각 | 사용자·단원 조합 고유. 완료 수 중복 방지 |
| DR-04 AI 결과 | A | 요청 ID, 소유 사용자, 원본 제출·출제포인트, 종류, 상태, 결과 또는 AI 문제 ID, 시각 | 본인만 접근. 원본 제출과 연결. 생성 중·실패·성공 구분 |

## 관계와 공개 범위

사용자 1명은 여러 제출 기록·완료 표시·AI 결과를 가진다. 일반 기출 1문제는 여러 제출과 관련 개념에 연결되지만, 기본 통계의 대표 개념은 하나다. 도전장 1개는 고정 문항 5개와 참가자 최대 2명의 최종 제출을 가진다. 게시글 1개에는 댓글 여러 개가 연결된다.

| 데이터 | 조회 가능 대상 | 변경 가능 대상 |
| --- | --- | --- | --- |
| 개념 및 기출 공개 본문 | 비회원 및 회원 | 자료 담당자의 등록 절차 |
| 정답과 기본 해설 | 본인의 제출 이후 결과 조회자 | 자료 담당자의 버전 관리 절차 |
| 개인 기록 및 AI 결과 | 본인 | 서버 검증을 통과한 본인 요청 |
| 도전장 정답 및 결과 | 양쪽 제출 완료 후 해당 2명 | 서버 채점·결과 계산 |
| 게시글 및 댓글 | D02에서 정한 독자 | 본인 글 수정·삭제 및 본인 댓글 작성 |

## 상태 전이

| 대상 | 정상 흐름 | 실패 및 재시도 |
| --- | --- | --- | --- |
| 일반 풀이 | 미선택 → 입력 완료 → 제출 중 → 저장 완료 | 실패 시 입력 유지. 같은 요청으로 확인·재시도 |
| AI 요청 | 요청 → 생성 중 → 검증 → 저장 완료 | 검증·호출·저장 실패 → 실패 안내 → 허용 시 재시도 |
| 도전장 | 생성자 풀이 → 생성자 제출 → 참가 대기 → 참가자 풀이 → 결과 완료 | 잘못된 참가·제출은 상태 변경 없음. 최종 제출 후 수정 불가 |
| 게시글 | 작성 → 공개 → 수정 또는 삭제 | 저장 실패는 기존 상태 유지. 삭제 확인 취소는 변경 없음 |

## 기존 브라우저 기록 처리

현재 localStorage에 남은 게스트 기록은 계정 기록과 자동 합치지 않는 것을 제안한다. 누가 작성한 기록인지 검증할 수 없기 때문이다. 서버 전환 시 이 사실을 안내하고 새 계정 기록으로 시작한다. 이전 기록 가져오기가 필요하면 별도 동의·중복 처리 정책을 정한다. 예전 샘플 3문항은 기출 통계에 포함하지 않는다.
