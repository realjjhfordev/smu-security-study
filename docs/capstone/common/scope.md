# 프로젝트 범위

[문서 안내](../README.md)

## 개발 목적

정보보안기사 필기 학습 자료, 문제풀이, 복습, AI 보완 학습을 하나의 웹 서비스에서 제공한다. 사용자는 단원·개념별로 학습 범위를 정하고, 자신의 최초 풀이 결과를 통해 약점을 확인한다. 두 사용자는 비동기 도전장과 게시판을 통해 학습 결과와 질문을 공유한다.

## 필수 범위

| 구분 | 제공 범위 |
| --- | --- |
| 회원 | 이메일 가입·로그인·로그아웃 및 사용자별 접근 권한 |
| 개념학습 | 7 PART·42 SECTION 요약, 검색, 관련 문제 연결, 학습 완료 |
| 문제풀이 | 기출·AI 공통 화면, 보기·확신도, 서버 채점과 기본 해설 |
| 복습 분석 | 계정별 기록, 오답·헷갈림 복습, 개념별 첫 정답률·취약 표시 |
| AI 학습 | 요청형 추가 해설, 같은 출제포인트의 보완문제 1개 생성·저장·재풀이 |
| 도전장 | 두 계정의 동일 5문항 풀이, 초대 링크, 점수·승패, 내 목록 |
| 게시판 | 목록·상세·작성·수정·삭제와 댓글 작성·조회 |

## 우선순위 등급

필수 기능 28개는 모두 만든다. 다만 각 기능의 세부 기준·비기능 요구사항·업무 규칙에는 아래 등급을 붙여 먼저 할 일과 나중에 할 일을 나눈다.

| 등급 | 뜻 | 처리 시점 | 미달 시 |
| --- | --- | --- | --- |
| **A 시연 필수** | 계획서의 시연 완료 기준 ①~⑥이 성립하는 데 꼭 필요한 기준 | 해당 마일스톤에서 가장 먼저 | 그 기능은 미완료 |
| **B 권장** | 보안·데이터 정확성을 위한 기준. 발표 질의응답에서 확인될 가능성이 높다 | A를 끝낸 뒤 같은 마일스톤 안에서 | 기능 완료는 인정하되 판정 열에 '미충족'으로 남긴다 |
| **C 여유 시** | 운영 서비스 수준의 기준(버전 관리, 장애 주입 시험, 성능 측정, 다수 브라우저 검증 등) | 전체 A·B를 끝낸 뒤 시간이 남을 때 | '미실시'로 남겨도 된다 |

등급을 바꾸려면 [미확정 정책과 근거](decisions.md)의 결정 이력에 적는다. AI에게 작업을 맡길 때는 A 기준부터 구현하도록 지시한다.

## 제외 및 선택 범위

실시간 대결·채팅·랭킹·랜덤 매칭·모바일 전용 앱·관리자 편집기·학습 효과 실험·자동 이중 AI 검증은 필수 범위에서 제외한다. 북마크·메모·간격 복습·미니 모의고사·문항 신고·도전장 오답의 개인 복습 연결은 필수 기능 완료 후 별도 요구사항으로 관리한다.

## 운영 제약

팀은 공용 저장소·DB·배포 주소를 사용한다. 배포·DB·인증·AI는 무료 범위에서 운영하고 한도 초과 시 기능을 멈춰 안내한다. 유료 플랜이나 체험 종료 후 과금되는 구성은 도입하지 않는다. 제공업체와 한도는 도입 시 재확인한다.

현재 구현은 Next.js와 Vercel 배포를 사용한다. 계획서는 공용 Supabase 프로젝트를 제시한다. 본 문서는 서비스 제공업체별 API 설계가 아니라 시스템이 충족할 동작을 규정한다.
