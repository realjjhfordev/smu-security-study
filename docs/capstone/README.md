# 요구사항과 실작업 문서

원본: `smu-security-study-requirements.docx` 0.9(2026-11-12).
현재 Markdown 버전: **0.9.2(2026-11-16)** — 우선순위 등급, 11/16 구현 상태 판정, 단계별 시험 절차 반영.
기능 28개, 공통 업무 규칙, 데이터·권한, 품질 기준, 시험 20개를 유지하면서 여러 파일로 나눴다.
이번 변경은 문서 구조 개편이며 실제 프로그램 기능을 수정하거나 최신 구현을 재검증한 작업이 아니다.

## 프로젝트에 넣기

1. ZIP을 임시 폴더에 풀어. 안에는 `마일스톤.md`와 `docs` 폴더가 있어.
2. `마일스톤.md`를 `C:\smu-security-study\마일스톤.md`에 복사해.
3. `docs/capstone` 폴더를 `C:\smu-security-study\docs\capstone`에 복사해. 기존 `docs` 전체를 지우면 안 돼.
4. 같은 이름의 파일이 이미 있으면 먼저 변경 내용을 비교해. 팀원이 작성한 기록을 그대로 덮어쓰면 안 돼.
5. VS Code에서 프로젝트 폴더를 열고 `마일스톤.md`를 열어. Markdown 미리 보기는 `Ctrl+Shift+V`로 볼 수 있어.
6. GitHub Desktop에서 추가 파일을 확인하고 개인 브랜치에 커밋·Push한 뒤 PR로 main에 반영해.

커밋 메시지 예시: `docs: 요구사항 분할 및 마일스톤 작업 문서 추가`
이 패키지는 코드·설정·기존 README·AGENTS.md를 교체하지 않아.

## 폴더의 역할

- `milestones/`: 단계별 할 일·담당·선행 작업·완료 조건과 작업 기록.
- `requirements/`: 기능 하나당 파일 하나. 입력·처리·결과·예외·수용 기준.
- `common/`: 기능들이 함께 쓰는 범위·규칙·데이터·품질·정책. 필요한 파일만 읽는다.
- `tests/`: 시험 하나당 파일 하나. 절차·기대 결과·실제 시험 기록.
- `working/`: 작업하며 확정할 환경·연결 규격과 문서 검증 도구.

## 한 내용은 한 곳에서 관리

상세 요구사항은 기능 파일, 작업 체크는 단계 파일, 시험 결과는 시험 파일, 정책 확정은 decisions.md에 기록한다.
마일스톤 첫 파일은 전체 단계의 완료 여부만 요약한다. 같은 상세 내용을 여러 파일에 복제하지 않는다.
Word 문서는 기존 제출용 스냅샷으로 남긴다. 앞으로 작업 기준을 바꾸면 Markdown을 먼저 갱신하고, 제출 때 Word 문서에도 같은 내용을 반영한다.

## 문서 연결 검사

Python이 설치되어 있다면 프로젝트 루트에서 `python docs/capstone/working/check_docs.py`로 상대 링크와 기능·시험 파일 수, 필수 명세 항목을 검사할 수 있어. 프로그램 기능 시험을 대신하는 검사는 아니야.
