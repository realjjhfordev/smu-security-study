# FR-QST-03 서버 채점과 답안 저장

- 우선순위: 필수 기능 · 세부 기준은 A/B/C 등급([등급 정의](../../common/scope.md))
- 담당: 윤도경 및 곽다인
- 작업 체크: [M02](../../milestones/M02.md)에서 관리
- 현재 상태(2026-11-16, main 433584c): **부분(브라우저 채점)**
- 완료 판정: 아래 A 기준을 모두 충족하고 연결 시험의 A 단계가 합격하면 기능 완료로 체크한다. B·C는 판정 열만 갱신한다.

## 필요한 문서만 읽기

- 선행·관련 요구사항: [FR-AUTH-04](../auth/FR-AUTH-04.md), [FR-REV-01](../rev/FR-REV-01.md), [DR-03](../../common/data.md)
- 집계·채점·공개 시점: [공통 업무 규칙](../../common/rules.md)의 관련 ID만 확인

## 시작 조건

로그인 및 문제 접근 권한이 유효하다. 답과 확신도를 선택했다.

## 입력

문제 ID·버전, 보기 번호, 확신도, 풀이 종류, 중복 방지 요청 ID. 정답 여부·사용자 ID는 서버에서 결정한다.

## 처리 흐름

1. 서버가 로그인·문제·입력 범위를 검증한다.
2. 보관된 정답과 비교한다.
3. 서버 시각과 결과를 하나의 제출 기록으로 저장한다.
4. 저장 성공 후 결과를 반환한다.

## 출력과 저장

일반 기출·AI에는 제출 ID·정오답·선택 답·정답·해설을 반환한다. 도전장은 [FR-CHL-03](../chl/FR-CHL-03.md)의 공개 제한을 적용한다. 동일 요청 ID에는 기존 결과를 반환한다.

## 예외 처리

범위 밖 답안, 변조된 사용자·문제 버전은 거부한다. 저장 실패는 성공으로 표시하지 않는다. 응답 유실 후 재요청해도 기록·점수가 중복 증가하지 않는다.

## 현재 상태와 남은 일

채점과 기록 저장이 브라우저에서 이루어짐(QuestionCard.submit, localStorage 'smu-question-attempts-v1').

- [ ] 서버 채점 API(로그인 사용자·문제·답 검증 → 저장된 정답과 비교)
- [ ] 제출 기록을 계정별로 DB에 저장
- [ ] 저장 성공 후 결과 반환

## 구현 작업 순서

1. 관련 코드와 최신 브랜치를 확인하고 현재 동작을 재현한다. 이미 충족한 부분은 유지한다.
2. 입력 검증과 위 처리 흐름을 구현한다. 권한·채점·저장은 해당 서버 경계에서 처리한다.
3. 실패·빈 결과·재시도 경로를 구현하고 기존 기능 연결을 확인한다.
4. 위 수용 기준과 아래 연결 시험을 수행해 증거를 남긴다. 미실시 항목은 완료로 표시하지 않는다.
