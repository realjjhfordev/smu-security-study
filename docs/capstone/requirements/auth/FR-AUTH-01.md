# FR-AUTH-01 이메일 회원가입

- 우선순위: 필수 기능 · 세부 기준은 A/B/C 등급([등급 정의](../../common/scope.md))
- 담당: 안재우
- 작업 체크: [M01](../../milestones/M01.md)에서 관리
- 현재 상태(2026-11-16, main 433584c): **목업**
- 완료 판정: 아래 A 기준을 모두 충족하고 연결 시험의 A 단계가 합격하면 기능 완료로 체크한다. B·C는 판정 열만 갱신한다.

## 필요한 문서만 읽기

- 선행·관련 요구사항: [FR-AUTH-02](FR-AUTH-02.md), [DR-01](../../common/data.md), [NFR-SEC-01](../../common/quality.md)

## 시작 조건

비회원이 회원가입 화면에 접근한다.

## 입력

닉네임, 이메일, 비밀번호, 비밀번호 확인. 길이·이메일 확인 정책은 D01을 적용한다.

## 처리 흐름

1. 필수값·이메일 형식·두 비밀번호 일치를 검사한다.
2. 인증 서비스에 가입을 요청한다.
3. 성공한 사용자 식별자로 프로필을 생성한다.
4. 이메일 확인이 필요한 경우 확인 대기 상태를 안내한다.

## 출력과 저장

계정과 프로필을 저장하고 가입 결과를 표시한다. 비밀번호 원문은 자체 테이블·로그에 저장하지 않는다.

## 예외 처리

중복 이메일, 불일치, 형식 오류는 해당 입력을 안내한다. 통신 실패를 가입 성공으로 표시하지 않으며 재시도를 제공한다.

## 현재 상태와 남은 일

가입 화면과 비밀번호 일치 검사만 있음. 입력은 전송·저장되지 않음(AuthMockup.tsx).

- [ ] 인증 서비스 가입 연동
- [ ] 가입 성공 시 프로필(닉네임) 생성
- [ ] D01에 따른 이메일 확인 대기 처리

## 구현 작업 순서

1. 관련 코드와 최신 브랜치를 확인하고 현재 동작을 재현한다. 이미 충족한 부분은 유지한다.
2. 입력 검증과 위 처리 흐름을 구현한다. 권한·채점·저장은 해당 서버 경계에서 처리한다.
3. 실패·빈 결과·재시도 경로를 구현하고 기존 기능 연결을 확인한다.
4. 위 수용 기준과 아래 연결 시험을 수행해 증거를 남긴다. 미실시 항목은 완료로 표시하지 않는다.
