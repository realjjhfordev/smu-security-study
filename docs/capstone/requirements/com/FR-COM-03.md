# FR-COM-03 게시글 수정과 삭제

- 우선순위: 필수 기능 · 세부 기준은 A/B/C 등급([등급 정의](../../common/scope.md))
- 담당: 안재우
- 작업 체크: [M06](../../milestones/M06.md)에서 관리
- 현재 상태(2026-11-16, main 433584c): **미구현**
- 완료 판정: 아래 A 기준을 모두 충족하고 연결 시험의 A 단계가 합격하면 기능 완료로 체크한다. B·C는 판정 열만 갱신한다.

## 필요한 문서만 읽기

- 선행·관련 요구사항: [FR-COM-01](FR-COM-01.md), [FR-AUTH-04](../auth/FR-AUTH-04.md), [DR-06](../../common/data.md)

## 시작 조건

로그인 사용자가 자신이 작성한 글을 열었다.

## 입력

글 ID와 변경 제목·본문 또는 삭제 확인.

## 처리 흐름

1. 서버에서 작성자 권한을 확인한다.
2. 수정은 동일 글의 내용과 수정 시각을 저장한다.
3. 삭제는 확인 후 글을 목록·상세에서 숨긴다.
4. 연관 댓글 처리에는 D06을 적용한다.

## 출력과 저장

수정 결과가 다른 계정에도 보인다. 삭제 후 목록으로 이동한다. 확인 취소는 내용을 변경하지 않는다.

## 예외 처리

타인의 수정·삭제 요청은 거부한다. 이미 삭제된 글은 안내한다. 동시 수정 충돌은 최신 내용을 다시 확인하도록 안내하며 조용히 덮어쓰지 않는다.

| A | A의 글에는 A에게만 수정·삭제 버튼이 보이고, 수정 내용은 B에게도 보이며, 삭제하면 목록·상세에서 사라진다. | 미충족 |
| A | B가 요청을 직접 조작해도 A의 글은 바뀌지 않는다. 삭제 확인을 취소하면 글이 유지된다. | 미충족 |
| C | 동시 수정 충돌 시 최신 내용을 확인하도록 안내한다. | 미충족 |

## 현재 상태와 남은 일

수정·삭제 기능 없음.

- [ ] 작성자에게만 수정·삭제 버튼
- [ ] 서버 쪽 작성자 권한 검사
- [ ] 삭제 확인

## 구현 작업 순서

1. 관련 코드와 최신 브랜치를 확인하고 현재 동작을 재현한다. 이미 충족한 부분은 유지한다.
2. 입력 검증과 위 처리 흐름을 구현한다. 권한·채점·저장은 해당 서버 경계에서 처리한다.
3. 실패·빈 결과·재시도 경로를 구현하고 기존 기능 연결을 확인한다.
4. 위 수용 기준과 아래 연결 시험을 수행해 증거를 남긴다. 미실시 항목은 완료로 표시하지 않는다.
