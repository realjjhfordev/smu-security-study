# AI 작업 안내 — 필요한 파일부터 읽기

## 처음 읽을 순서

1. 프로젝트에 기존 AGENTS.md 등 적용되는 지침이 있으면 먼저 따른다. 이 문서는 그 지침을 대체하지 않는다.
2. [마일스톤.md](../../마일스톤.md)에서 맡은 단계만 선택한다.
3. 해당 `milestones/Mxx.md`에서 작업 하나를 고른다.
4. 연결된 `requirements/<분야>/FR-*.md` 한 개를 읽는다.
5. 그 기능에 필요한 공통 규칙·데이터·정책과 연결 시험만 추가로 읽는다. 선행 요구사항은 현재 작업에 필요한 부분만 확인한다.
6. 파일 경로나 심볼을 검색해 실제 코드의 관련 부분을 확인한다. 현재 상태는 문서의 옛 상태 표만 보고 판단하지 않는다.

전체 문서의 일괄 출력·모든 파일 재귀 읽기를 기본 행동으로 삼지 않는다. 다만 권한·채점·저장·여러 기능 공통 코드의 영향을 확인하는 데 필요한 문서는 생략하지 않는다.

## 작업할 때 지킬 것

- 수용 기준 표의 A 등급부터 구현한다. B는 A가 끝난 뒤, C는 사용자가 요청할 때만 구현한다. 작업 후 판정 열을 실제 결과로 갱신한다.
- 기능 ID와 Q번호를 임의로 바꾸지 않는다. 제안 정책 D01~D08을 승인된 규칙으로 간주하지 않는다.
- 정책이 필요한 부분은 결정 내용부터 확인한다. 막힌 부분을 기록하고 독립적으로 할 수 있는 작업을 진행한다.
- 공용 데이터 형식 변경은 [연결 규격](working/contracts.md)에 적고 관련 담당자·기능 영향을 확인한다.
- 문서만으로 실제 파일명·DB 테이블·API 주소를 추측해 확정하지 않는다. 실제 코드와 설정을 확인한다.
- UI 목업, 로컬 저장, 테스트용 고정 응답을 실제 인증·서버 저장·AI 연동의 완료 증거로 삼지 않는다.
- 관련 기능 수용 기준과 시험을 수행한다. 실행하지 못한 시험은 미실시와 이유를 남긴다.
- 작업 끝에는 단계 파일에 변경 파일·커밋/PR·수용 기준 확인 내역을, 시험 파일에 실제 결과를 기록한다.
- 자동 Push·Merge를 이 문서가 허가하는 것은 아니다. 사용자의 지시와 저장소 지침에 따라 진행한다.

## 그대로 복사해서 AI에게 요청하기

```text
이 프로젝트의 마일스톤.md와 docs/capstone/AI-작업안내.md를 읽어.
이번 작업은 FR-QST-03 서버 채점과 답안 저장이야.
M02 단계와 해당 기능 파일, 거기서 연결된 필요한 규칙·데이터·시험만 읽어.
수용 기준 표의 A 등급부터 구현해. B는 A가 끝난 뒤에 진행하고, C는 내가 요청할 때만 진행해.
전체 문서를 한 번에 읽지 말고 실제 관련 코드를 확인해서 이미 된 부분과 남은 일을 구분해.
미확정 정책이 있으면 해당 작업에 어떤 영향이 있는지 알려줘.
작업 후에는 관련 시험을 실행하고, 실제 확인한 결과만 작업 기록에 남겨.
```

다른 일을 맡길 때는 기능 ID와 M단계를 바꿔. 특정 기능을 아직 정하지 못했다면 담당 단계에서 다음 미완료 작업 하나를 고르도록 요청하면 돼.
